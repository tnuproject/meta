## Features

Complexity is relative to this project: low, medium, high. amd64 is the only architecture;
"portable" means that nothing in the feature itself prevents others.

### Hardware discovery

| | |
|---|---|
| Feasibility | Yes. FreeBSD reports PCI, USB and ACPI devices |
| FreeBSD interfaces | `pciconf -l -c`, `usbconfig`, `devinfo -v` |
| Upstream | None |
| Kernel | None |
| Security | Read-only. USB descriptors need root; without it they are reported as unavailable |
| Limits | Portable. I2C and SDIO devices only as far as ACPI names them |
| Complexity | Low |
| Accepted when | Every device of a captured system is listed, a missing tool is reported rather than taken as no hardware, and nothing on the system changes |

### Compatibility database and evaluator

| | |
|---|---|
| Feasibility | Yes |
| FreeBSD interfaces | `kern.osreldate`, `hw.machine_arch`, `kldstat`, `kern.conftxt`, `pkg` |
| Upstream | Manual pages and status reports as sources |
| Kernel | Versions and options are compared, not assumed |
| Security | Data only. Every entry needs a source; every validation needs a test |
| Limits | 29 entries. Three are validated, all virtual hardware |
| Complexity | Medium |
| Accepted when | CONFIRMED appears only for a tested device on the tested major release, and missing facts lead to INSUFFICIENT_EVIDENCE |

### LinuxKPI registry

| | |
|---|---|
| Feasibility | Yes, from source. Behaviour cannot be read from declarations |
| FreeBSD interfaces | `sys/compat/linuxkpi` |
| Upstream | Regenerated for every release by `compatibility/generate.py` |
| Kernel | One registry per release |
| Security | None |
| Limits | Names generated by macros are not found |
| Complexity | Medium |
| Accepted when | Regeneration gives the same file, and a declared function is never reported as working |

### Driver prediction (MPDC)

| | |
|---|---|
| Feasibility | As a hint for porters; not as proof |
| FreeBSD interfaces | None at run time |
| Upstream | Driver source |
| Kernel | None |
| Security | Reads text. Never builds, loads or patches |
| Limits | Names, not behaviour |
| Complexity | Medium |
| Accepted when | It never says CONFIRMED, and drivers known to work are not called INCOMPATIBLE |

### Firmware

| | |
|---|---|
| Feasibility | Yes, through FreeBSD's own tool |
| FreeBSD interfaces | `fwget(8)`, `pkg(8)`, `dmesg` |
| Upstream | `wifi-firmware-*`, `gpu-firmware-*` packages |
| Kernel | Drivers load firmware by name |
| Security | Signed packages only. META redistributes none |
| Limits | What fwget knows |
| Complexity | Low |
| Accepted when | Nothing is listed that fwget does not name, and requests the kernel failed are shown |

### Driver life cycle

| | |
|---|---|
| Feasibility | Yes |
| FreeBSD interfaces | `pkg`, `kldload`, `sysrc` (`kld_list`) |
| Upstream | Packages |
| Kernel | Modules matching the running kernel |
| Security | A plan, then `--yes`; untested components need `--accept-untested`. No module is unloaded |
| Limits | No undo after a failure, only the commands for it. No rollback when a driver hangs the machine; a boot environment helps |
| Complexity | Medium |
| Accepted when | Nothing changes without confirmation, and disabling restores the previous state |

### Virtual machines

| | |
|---|---|
| Feasibility | Yes |
| FreeBSD interfaces | `bhyve`, `bhyvectl`, `vmm`, `jail`, `devfs`, `nullfs`, `makefs`, ZFS |
| Upstream | `edk2-bhyve`, `libslirp`, `qemu-tools` (image conversion) |
| Kernel | `vmm`; a processor with VT-x or SVM, nested paging |
| Security | See [SECURITY](SECURITY.md) |
| Limits | amd64. No suspend, snapshot of a running machine, or migration |
| Complexity | High |
| Accepted when | A distribution boots with its own kernel and systemd, powers off when asked, restarts itself when the guest reboots, and leaves nothing behind |

### Debian and Arch guests

| | |
|---|---|
| Feasibility | Yes: official cloud images with cloud-init |
| FreeBSD interfaces | None further |
| Upstream | Debian 12 and Arch cloud images |
| Kernel | Guest's own |
| Security | Digest in the repository; host key made by META and pinned |
| Limits | cgroup v1 needs Debian 12; Arch's systemd no longer has it |
| Complexity | Medium |
| Accepted when | systemd, a namespace, a cgroup limit and a loaded kernel module are seen inside the guest |

### Files and network

| | |
|---|---|
| Feasibility | Yes: virtio-9p and slirp |
| FreeBSD interfaces | bhyve's 9p server, `bhyve-slirp-helper` |
| Upstream | libslirp. The restricted mode of 15.1 fails for root; running as a user avoids it |
| Kernel | 9p in the guest |
| Security | `nosuid` dataset; ports on loopback only |
| Limits | 9p is slow. An open network also reaches the host's loopback services |
| Complexity | Medium |
| Accepted when | Files pass both ways with the owner's identity, and an isolated guest reaches nothing |

### Program analysis

| | |
|---|---|
| Feasibility | Partly. What a program does can only be observed |
| FreeBSD interfaces | `truss(1)` for trials |
| Upstream | None |
| Kernel | None |
| Security | Trials run as the calling user, never as root, and only when asked for |
| Limits | Plugins, helper programs and scripts are not followed |
| Complexity | Medium |
| Accepted when | Stated needs and hints are kept apart, each with evidence |

### Runtime selection

| | |
|---|---|
| Feasibility | Yes |
| FreeBSD interfaces | None further |
| Upstream | None |
| Kernel | The registry of system calls is per release |
| Security | Options restrict the choice and cannot override a missing requirement |
| Limits | As good as the analysis |
| Complexity | Medium |
| Accepted when | The least demanding runtime is chosen and every rejection is explained |

### Launching

| | |
|---|---|
| Feasibility | Yes |
| FreeBSD interfaces | `execve`, `jexec`, `ssh` |
| Upstream | OpenSSH |
| Kernel | None |
| Security | Arguments are quoted once, for the guest's shell; only terminal and language variables are passed |
| Limits | A program that stops itself (SIGTSTP) is not reflected on the host |
| Complexity | Medium |
| Accepted when | Arguments, standard streams, exit codes and signals match a local run |

### Containers

| | |
|---|---|
| Feasibility | In a machine only |
| FreeBSD interfaces | None |
| Upstream | Docker, Podman, containerd from the guest's distribution |
| Kernel | Guest's namespaces, cgroups, overlayfs, netfilter |
| Security | Containers are separated from the host by the machine. Not jails |
| Limits | Installing an engine and pulling images needs an open network |
| Complexity | Low |
| Accepted when | An OCI image runs under each engine and its exit code arrives |

### Graphical programs

| | |
|---|---|
| Feasibility | X11 without acceleration. Wayland needs a proxy such as waypipe |
| FreeBSD interfaces | X server |
| Upstream | `xauth` in host and guest |
| Kernel | bhyve has no virtio-gpu |
| Security | Untrusted X11 forwarding is not usable for most programs; a forwarded program can watch the display. Never without `--x11` |
| Limits | No acceleration, no audio |
| Complexity | Medium for X11, high for anything else |
| Accepted when | A window of a guest's program appears on the host's display, and does not without `--x11` |
